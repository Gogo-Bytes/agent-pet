# #20 设计复审：先批判，再修改

基线：`9c6902c`。这是既有两轮清理后的增量复审，不把历史改动冒充本轮成果。研究依据见[界面内容设计规范](../../UI-CONTENT-DESIGN.md)。

## 批判

从用户角度，进入连接页通常只为知道“连上了吗”和“下一步做什么”，不是来阅读接入协议。此前清理缩短了句子，却仍保留了一些“每个区域都必须有解释”的结构。

| 当前证据 | 问题与代价 | 决策 |
| --- | --- | --- |
| `ConnectionsView` 空状态：“从第一个连接开始”“自动扫描，或手动添加你的 Agent。”；同屏已有扫描和添加控件 | 标题是劝导语而非状态，正文复述入口。多读一段，没有多获得一个决策依据。 | 标题改为“还没有连接”；删除复述，保留读取中的反馈。 |
| `ClaudeConnectionControls` 的 `cfg-claude-scope` 常驻完整能力清单 | 把能力文档放在每次连接检查的主路径，与状态和主按钮竞争。 | 日常详情移入“支持哪些反馈？”；启用确认仍直接显示能力与限制。 |
| Claude 暂停时既有 summary 又有 disabled notice；旧命令模式还会重复“打开新的 Claude Code” | 多个段落争着讲同一状态，读者需要猜测是不是多项要求。 | 有具体 notice 时不再呈现泛化 summary；保留 notice 播报、命令输入及操作提示。 |
| Codex 在线标题“已连接”以外，还给屏幕阅读器保留“Codex 已连接。” | 只是把重复从视觉路径转移给另一类用户，不是真正精简。 | summary 不再携带这句重复正文；标题仍提供状态。 |
| Claude/Codex 失败 summary 的“请查看提示”与具体错误并列 | 泛化指令不能帮助恢复，还稀释了真正错误。 | 有具体 notice 时隐藏泛化 summary，不删错误和保留文件说明。 |

## 对“极简”的反向批判

- 不能按字数或 `<p>` 数量判断好坏。移除确认、写入路径、是否影响 Agent 运行都直接影响授权判断。
- 折叠不是垃圾桶：重复内容应删除，只有有用但低频的内容才折叠。不能把首次连接所需的 `/reload` 或 `/hooks` 藏掉。
- “布局自己说明”也有边界。用户不能从图标猜到输入格式、加载失败原因或操作后果；可访问名称不能删。
- 当前暂停、恢复、移除的术语必须继续区分；不为减少几个字把所有动作统一成“确定”。

## 本轮边界

增量改动限于连接页的重复信息和能力说明层级，不改变 Provider 状态、权限、文件写入或恢复逻辑。现有来源清点见同目录 README；本轮不重做已完成的设置/通知清理，也不删除说明中真实的限制。研究结论是设计判断，不是可用性实验或已测得的效率提升。

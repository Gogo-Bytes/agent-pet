# P0：pi 受管理扩展安装与撤销契约（评审草案）

状态：**设计，不是安装器实现或已通过的事务验证。** 接续 [产品设计](DESKTOP-PRODUCT-DESIGN.md)、[P0 接入契约](P0-INTEGRATION-CONTRACT.md) 与 [本机安全边界](P0-LOCAL-SECURITY-DECISION.md)。本轮允许临时配置目录下的发现验证，不允许真实用户配置写入或 Agent 执行。

## 1. 最小承诺

用户点击一次授权，应用部署一个自身拥有的观测扩展；以后的正常 pi 启动自动发现。整个过程不要求终端、不增加全局 npm 包、不改 shell、不改共享 settings/trust、不控制 pi。

支持范围先限定已核实的标准 pi 发行版和可验证的用户级配置目标。`<agentDir>/extensions/agent-pet.ts` 是候选产品专属入口名；存在同名未知文件时不覆盖、不换一个随机扩展名绕过冲突，避免加载两份相同逻辑。

目录可存在不代表该目录属于当前使用的 pi。发现安装、部署文件、握手在线、真实工作事件分别提供证据；尚未在线时允许正常“等待会话”，不虚报安装失败。

## 2. 权威数据与边界

由 Main 管理，Renderer 只拿脱敏投影：

- `targetId`：授权配置目标的不透明 ID；以规范化配置目录识别是否重复注册。不是 pi session ID 或 executable ID。
- `authorization`：pending / enabled / revoked，附 epoch。目标 token 仅用于此授权，不能以 token 文件存在自动恢复 enabled。
- `deployment`：目标文件位置、安装版本、产品 payload 摘要、部署后文件摘要、必要文件身份信息。
- `operation`：本次动作与预期旧版本/摘要、计划阶段、暂存路径和失败原因。只供崩溃恢复，不是永久无界事件日志。
- `runtime`：当前握手连接集合、已协商协议、最后连接结果。文件部署版本和运行中扩展版本分别展示。

只有一个 Main 写入上述状态；单实例锁不等于多安装目录/多 release channel 的全局锁。预览版与未来正式版的命名空间需在打包前冻结，不能让两套产品同时拥有同一个 pi 文件。

所谓“只读 Agent”是指不控制推理/消息/审批；安装扩展仍是用户授权的配置写入，必须明确告知，不应宣称整个产品从不写 pi 目录。

## 3. 第一次安装

### 检测与变更预览

1. 用户选定目标；Main 验证受支持 pi/目标范围、目录所有权和可接受的路径/权限，拒绝未知 symlink 等不安全输入。
2. 检查现有目标文件及自动发现阻碍。root index/manifest、用户排除/ignore、禁用扩展等不自动修复；说明“此目标需要处理冲突”，不能为了成功修改用户规则。
3. 展示新增的产品扩展、采集字段、仅本机连接、已有会话生效条件和撤销入口。确认前不写 pi 配置目录。

### 应用

1. 锁定本目标操作，重新校验预览时状态；状态变更则废弃旧预览，请用户重试。
2. 在产品私有目录持久化 pending 意图与可恢复清单；生成按目标凭证，但 pending 不准入 Session 数据。
3. 准备自包含扩展 payload。秘密不进入源码；只有受限非秘密 bootstrap/目标标识。校验随包资源和 payload 摘要。
4. 同目录暂存使用不可发现后缀且权限明确，最终创建必须**不覆盖已有目标**。不能用 `exists → rename` 声称实现原子的 no-clobber；发布原语需选定并测试。无需临时复制成另一份 `.ts/.js`。
5. 验证最终文件内容与所有权记录匹配，提交 deployment，然后启用授权。任何已提前加载的扩展只会等待或被 pending 拒绝，重试后生效。
6. UI 显示“已配置，等待 pi 加载”；握手成功后显示在线与运行版本。不能因为静态 resolver 列出文件就显示已加载。

取消只允许安全边界：确认前立即取消；写入期间请求取消由 Main 完成必要清理后返回，不让 UI 假装取消而后台继续授权。

## 4. 安装中断与恢复

| 重启后看到的状态 | 处理 |
| --- | --- |
| pending，无最终文件 | 授权保持无效；清理可证明属于本操作的暂存项，显示未完成 |
| pending，有匹配最终文件 | 不仅凭文件自动授权；依据已持久化用户确认/操作记录核对后完成或展示“继续/撤销”；不能绕过缺失的同意证据 |
| pending，目标文件不匹配 | 保留用户文件，撤销本次准入，显示冲突 |
| enabled，文件匹配 | 已配置；等待运行连接 |
| enabled，文件缺失/变更 | 标记部署需修复，不自动覆写；运行连接状态单独显示。若安全完整性策略要求暂停，必须准确提示而非伪造 Agent 错误 |
| revoked，无论文件是否残留 | 始终拒绝准入；仅尝试选择性清理，不自动复活授权 |
| 授权记录损坏/无法读取 | fail closed；凭证和旧文件不作为 enabled 证据，用户从界面修复 |

原子 rename 不等于断电耐久性。写入/fsync/目录同步顺序与平台错误处理需验证；未验证前不保证所有突然断电恢复路径。

## 5. 升级与用户修改

- 首版无需后台自动更新扩展。随 Pet 升级检查兼容性，兼容旧扩展可继续；需要变更时展示明确状态和“更新接入”。不强迫用户正忙时重载。
- 更新前比较所有权、文件身份和最后部署摘要；不匹配则标为用户修改，保留内容。
- 旧版本备份放产品私有、非发现位置。更新失败保留可恢复旧版；不是在 extensions 下留 `agent-pet-old.ts`。
- 从已确认的旧版本切换到完整新文件，避免 pi 读到半文件。提交后运行中旧扩展继续按协商兼容范围服务，直到用户安全重载。
- 文件摘要检查不能证明不存在“检查后外部写入”的竞争。Node 的普通 rename 没有基于预期摘要的跨进程 CAS；不能声称绝对不会覆盖并发修改。选定方案必须记录此边界并做变更再检查/冲突保留；若不能达到承诺，不提供静默原地升级，改为显式暂停后的用户确认流程。
- 回滚只回滚产品拥有的匹配内容；磁盘回滚不等于运行时立刻回滚，不调用 pi reload。
- 新增采集字段或扩大权限需重新授权，不用“更新扩展”隐含许可。

## 6. 断开与移除

首版主按钮“断开连接”代表停止接收并移除自有扩展；执行前说明运行中的扩展可能保留至 pi 下次重载，但已无接入权限。高级的“仅暂停”非首版必要能力，避免混淆。

顺序：

1. 在内存立即拒绝本目标新/后续消息，关闭其现存连接。
2. 持久化 revoked/epoch 并确认成功。磁盘失败时本次仍停止接收，但 UI 显示“本次已停止，持久撤销失败”；不能显示完全断开。未保证持久性前不删除唯一授权/所有权证据。必要时停止该桥接实例，避免失败状态下继续接收。
3. 只移除仍匹配自有部署身份与内容的最终文件、凭证及暂存项。用户改动过则保留，显示残留路径的脱敏说明与手动处理入口。
4. 保留必要撤销/所有权记录以防残留扩展或重装复活；不保留不必要的 Session 数据或无限日志。重置产品数据必须与撤销/残留处理一并设计。
5. 不影响其它 target，不删除 agentDir，不恢复整份历史 settings。

直接拖删 App 没有可靠产品清理回调；文档与 GUI 提供卸载前清理入口。残留扩展在 Pet 不存在时安静退避、不保活 pi。以后重新安装 Pet，不仅凭旧凭证恢复未确认的目标。

## 7. 需验证的事务用例

- 取消授权：零 pi 文件改动。
- 目标同名未知文件/已有用户修改：零覆盖。
- 相同目标重复点击：幂等，不创建第二份扩展、凭证或桥接实例。
- 首次创建前外部占用目标：明确冲突，不覆盖。
- 每一个持久化/发布步骤注入失败：无静默 enabled、半文件或重复发现入口。
- 发现 root-entry/ignore/排除：解释原因，不清除用户规则。
- 扩展在 pending 时被 pi 发现：不获准发布 Session；授权完成后重试可用。
- 更新后的旧连接、磁盘版本与运行版本：状态准确，不自动重载。
- 断开后现存连接、队列消息、重启与残留文件：不能重新获准。
- 断开一个目标不影响另一个；断开与安装/升级同一目标串行。
- 私有存储损坏/写入失败：显示可恢复问题，不扩大权限、不误报成功。

上述用例是实施验收契约，目前不标为通过。临时 pi resolver 验证只能覆盖“哪些文件会被发现”，不能覆盖安装事务、扩展加载、事件、连接或 OS 权限。

## 8. P0 的收口边界

P0 交付应是：明确的版本/目标支持范围、发现证据、最小本机安全模型、安装/撤销流程、实施前必须解决的风险。它不是 P2 安装器完成证明。

建议在动态发现证据归档后进行一次整体设计评审：可批准 P1 管理窗口基础独立实施；P2 写真实目标前必须完成发布原语、持久撤销、路径权限和失败注入验证。证书生命周期不再阻塞 P1/P2；macOS 发布签名、公证与 Windows 后续验证仍保留。

# P1 管理窗口尺寸控件修复

用户验收：宠物显隐正常；桌宠工具栏调整会同步管理窗口，但管理窗口内不能调整；重启保留偏好与退出后再启动均通过。顶部托盘仍是独立未关闭项，Dock 恢复已获用户确认。

## 已复现缺陷与修复

`ManagementApp` 的 range 每次 change 都进入异步保存并设置 busy，父 fieldset disabled 导致滑块在第一次变化后被禁用；等待期间 value 又仍来自旧快照。新增延迟 IPC 的 DOM 用例实际驱动 range 后检查 `:disabled`，修复前失败（true），因此不能用原先立即 resolve 的单次 change 用例代表连续输入正常。

修复范围仅管理 Renderer：

- 滑块不因自身保存而被禁用；显示临时拖动值及“正在保存尺寸”，不将临时值称为已持久化。
- 每次只允许一个尺寸写入在途，连续输入合并为一个最新待写值，不并行乱序保存。
- 保存失败丢弃待写值并回到权威快照，保留错误提示，用户可重新尝试。
- 期间其它写操作暂禁用；组件卸载不继续发送排队请求。
- 用推送序号保护权威状态，较早请求的返回不覆盖已收到的更新推送。

Main 的尺寸范围、保存策略、pi 与模型均未改。未新增依赖，没有改真实偏好/Agent 配置，没有启动或重启用户应用。

## 证据

全量 `pnpm test`：27 文件 / **162 项通过**；`pnpm typecheck`、`pnpm --filter @agent-pet/desktop build`、`git diff --check` 通过。WebGL 测试仍有既有 Three.js 重复导入警告，无新增失败。

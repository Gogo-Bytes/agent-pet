# P0：本机接入安全边界与简化建议

状态：**推荐方案，待随技术设计评审；未实现，也未宣称权限验收通过。** 本文调整早期“实验成功所以继续完善 TLS”的方向，不改写历史实验结果。

## 1. 结论

macOS 预览版建议采用 **当前用户私有目录 + Unix domain socket + 按接入目标生成的随机 token**，不把 TLS、连接证书、Keychain helper 或常驻 daemon 作为首版必选项。

理由不是 TLS 无用，而是当前产品仅观察本机、同一系统用户主动授权的 pi。若发现文件、token 与 TLS 私钥/信任资料最终都由该用户权限保护，额外套一层 TLS 并不能独立解决同用户恶意程序读取 token、替换扩展或冒充服务的问题，却引入证书生成、到期、轮换与修复路径。

用户从始至终只看到“允许连接”“等待生效”“已连接”“断开/修复”。没有 token、证书、socket 或环境变量表单。

## 2. 明确保障与不保障

| 风险 | 首版方案与边界 |
| --- | --- |
| 其它普通 OS 用户读取凭证/连接 socket | 依靠私有目录、owner/mode/ACL 和安全路径策略；必须实机验证，不凭 chmod 成功就宣布隔离有效 |
| 无效配置、误连到另一实例 | 私有发现记录、实例 generation、协议版本、目标 token 与 ack 校验；不以 socket connect 即显示在线 |
| 未授权 Renderer 读秘密或安装任意文件 | Main 独占文件/秘密，窗口和 frame 级窄 IPC 授权，参数验证 |
| 已撤销目标继续发送 | 先持久化撤销，关已有连接，后续消息再次受授权状态约束，随后清理自有文件 |
| 认证前资源耗尽、错误消息 | 超时、连接上限、帧/缓冲限制、速率限制与异常隔离 |
| root、同 uid 恶意程序、恶意 pi 扩展 | **不承诺隔离**。这些主体可能读取文件和进程内存、改写扩展；按目标 token 不是同用户应用之间的强隔离 |
| 离机传输/局域网/远程接入 | **不支持**，不监听 TCP，不允许 socket 不可用时自动退回 TCP |

按目标 token 是用于准入、误用控制、撤销和凭证轮换的共享秘密，**不是密码学服务端身份认证**。ack 只表明应用层协议被接受，不证明对端是 Apple 签名的 Pet。客户端先发送 token 的安全前提是连接位置及其目录树符合约定权限边界，不能忽略路径验证然后声称等效 TLS。

token 明文 at rest，明文经过本地 socket；不写日志/诊断/renderer/命令行。操作系统权限保护是明确的设计取舍，不以“已加密”宣传，也不默默降级到宽权限目录。

## 3. 最小连接流程（候选）

1. 用户授权一个配置目标；Main 生成高熵随机 token，保存到受限制的产品私有凭证文件，不写入扩展源码。
2. Pet 获取单实例锁，在新实例独占的私有运行目录创建 socket，权限校验成功后原子发布发现记录。记录不含秘密，只含受限的实例/协议/endpoint/目标凭证引用。
3. 扩展首次连接和每次重试都重新发现；验证受支持路径范围、所有者、类型、权限及大小。credential reference 不是可任意读取文件的绝对路径指令。
4. 首帧仅发送协议版本、目标标识、实例 generation、token；此时不附会话名称、项目名或正文。
5. Main 检查有效授权、token、协议和实例，返回不含秘密的 ack；此后才接收最小 Session 状态。此 ack 不被称为双向密码学认证。
6. 授权撤销后先停止接收/关闭相关连接，再清理文件；清理失败仍为已撤销。Pet 重启重新建立运行记录，原授权可保持，但不能信任孤立残留文件恢复已撤销授权。

协议 schema、错误码、时间/容量上限和轮换时机仍需契约定稿；不增加自制加密/挑战应答。

## 4. 路径与权限是必须做的工作，不是被 TLS 替代的工作

- 仅使用本机文件系统下可确认安全的目录。私有目录目标 0700，秘密/发现文件目标 0600；socket 位于私有目录中并收紧权限。不能依赖 socket inode mode 在所有平台的相同行为。
- 新建实例目录避免共享固定 socket 被抢占。必须审查祖先目录和 ACL；拒绝未知 symlink、可疑 hardlink、宽松权限或不可信路径，不能为了“一键成功”修改整个用户 home/agentDir 的权限。
- 公共临时目录本身不提供身份保证。如果采用短临时路径，创建/定位/清理方式需要单独验证；不得把 `/tmp/agent-pet.sock` 当成安全固定地址。
- `O_NOFOLLOW` 仅保护 leaf 的对应 open，不等于整条路径防替换。保持 threat model 诚实，不声称纯 Node 已解决全部 TOCTOU。
- 在入口目录、凭证和实际 endpoint 不一致、无法安全解析或路径过长时失败关闭，界面给出可理解的原因；不盲删已有 socket。

这些要求之前已有来源与基础实验：[官方来源研究](P0-SECURITY-RELEASE-RESEARCH.md)、[首轮隔离实验](P0-ISOLATED-VALIDATION.md)。基础实验未覆盖跨用户 ACL 与恶意并发替换，因此方案目前仍是有条件的可行建议。

## 5. 何时重新引入 TLS 或更强机制

以下任何一个需求成立时重新设计，而不是直接把当前本机协议搬过去：

- 远程、跨机器、TCP 或不可信传输。
- 需要抵御同用户程序冒充服务，或验证应用代码签名身份。
- 凭证不能以用户私有明文文件保存。
- 用户环境无法建立所需文件/目录访问控制。

TLS 可解决不可信传输和在可信锚已安全分发条件下的对端证明；同用户应用隔离仍可能需要 OS 身份机制/窄 helper。它不是“开 TLS 即全部解决”。环境不满足首版边界时应明确不支持，不自动安装额外服务。

macOS 应用签名与公证仍需由发布者完成，与上述内部连接是否 TLS 无关，不能因此删除发布门槛。

## 6. 对 P0 的实际影响

取消首版必选工作：连接证书配置/生成/到期/轮换、TLS session ticket 撤销、Keychain helper。保留既有 TLS 实验作历史证据，不迁入生产。

保留必须完成的验证：

1. 真实 Node/Electron 的私有 UDS + 合成 token 握手/拒绝/撤销/重连实验。本轮已完成下述有界检查，持久撤销与重启恢复仍未验证。
2. 路径和权限策略，包括跨用户/ACL（需专用环境授权）、残留 socket、长路径；没有证据的场景明确不支持。
3. pi 临时配置目标的自动发现与冲突处理；不触碰用户实际配置。
4. 安装、升级、撤销与中断恢复事务；保持扩展单文件和目标所有权边界。

P0 的目的应是得到可实现、可测试的契约，不是提前写完产品。无需继续泛化到远程 Agent 或所有 OS；Windows 保持后续。

## 7. 本轮简化路径实验

临时脚本 `/tmp/ap-uds.ox6lpf/probe.cjs`，系统 Node 22.22.3 客户端与 `ELECTRON_RUN_AS_NODE=1` 的 Electron 36.9.5 内嵌 Node 22.19.0 服务端，经临时私有目录里的真实 UDS 通信。没有 TLS、证书、pi 进程、真实配置或产品代码改动；合成 token 仅在内存与父子 IPC，不写命令行/日志。socket 已正常删除，子进程已结束。

[private-uds.json](evidence/p0/private-uds.json) 记录 9 项通过：两个目标收到 ack；错误 token、未知目标、过期实例、错误协议均被拒绝；撤销关闭目标已有连接且阻止再次接入；另一个目标连接不受影响且可重连；stop 删除 socket。

**证据限度：** 只验证抛弃式候选逻辑和真实运行时传输。示例 framing 有意简化，不可迁入产品；没有跨用户 ACL 验证、攻击者服务身份验证、持久撤销/重启恢复或安装事务验证。token 字符串比较也是实验简化，不是最终比较实现。新实例路径和凭证发现尚未接上，不能声称完成零配置产品接入。

# 持续状态动画：in / loop / out

状态：设计已由用户确认，待实施。本文是后续实现与验收依据，不表示现有播放器已经支持。

## 目标与范围

只为系统明确允许的持续状态提供可选入场与退场动画。首批开放：

- `idle`：空闲。
- `working`：工作中。
- `dragging`：被拖动。

其他映射保持现有行为；不得仅因其当前播放方式为 loop 就自动开放 in/out。后续扩展须逐项确认。完成、错误、hover、selected 等单次事件不增加 in/out。

这三种阶段是播放器的视觉表现，不新增 Agent 业务状态，不修改 Provider 事件含义，不从动画名称推断业务状态。

本设计是对历史“一个触发项只映射一个准确 clip 名”的有界扩展；在实施完成前，旧格式和现有播放器仍是实际可用契约。本文不授权自动迁移、覆盖用户包或修改已安装资产。

## 动画配置

每个获准的持续状态可以指定：

| 阶段 | 行为 | 要求 |
| --- | --- | --- |
| in | 进入该状态时播放一次 | 可选 |
| loop | 状态持续期间循环播放 | 阶段配置的主体 |
| out | 正常离开该状态时播放一次 | 可选 |

示例：working 的 in 指向 `Dance_In`，loop 指向 `Dance_Loop`，没有退场素材就不配置 out。片段保留为独立 GLB clips；不把 in 和 loop 合并成一个整体循环，否则每轮都会重复入场。

旧包的字符串/null 映射继续兼容：已有字符串仍表示原先的单片段播放，不要求用户补字段或重新导入。配置使用准确 clip 名，不根据 `_In`、`_Out` 后缀自动配对。具体 JSON 形状、schema 版本及类型变更在实施时统一确定，不把本文示例当作当前可导入格式。

缺失或无效的可选 in/out 应跳过，不阻塞状态切换；主体缺失继续使用现有 fallback/静态行为，不播放一套没有有效主体的孤立过场。导入端的非法字段验证与资源限制仍保留。

## 状态切换契约

正常从 A 切换到 B：

```text
A.loop → A.out（可选，单次）→ B.in（可选，单次）→ B.loop
```

目标为单次事件时，最后一步为现有事件播放及完成后的恢复，不为它生成 loop。

### 去重与中断

1. 同状态重复通知或普通重渲染，不重新播放 in。
2. 多个工作细类若最终回退到同一套 working 映射，视为同一动画状态，继续当前阶段/循环。不能只因 thinking → reading 等原始状态名变化就重复入场，也不能仅凭两个不同配置恰好引用同名 clip 就将它们合并。
3. in 尚未结束就离开：立即切到最新目标，跳过尚未进入循环的旧状态 out；不强行播完入场或补齐整套过场。
4. out 期间目标改变：只保留最新目标，不排队；旧 out 不因每次通知重新开始。普通新目标在当前 out 完成后进入，即时反馈可直接打断 out。目标返回原状态时取消 out，恢复原 loop，不再重复 in。
5. 旧动作的迟到 finished 回调不能启动过时目标。所有权释放、换模型和卸载后不能继续播放。
6. in/out 只影响视觉播放，不延迟业务事实、通知或操作生效。

### 临时反馈与即时切换

- hover/selected 是临时反馈，不视为底层持续状态退出，不为它们播放底层 out/in；结束后恢复最新有效持续状态的 loop，不能恢复已过时的业务状态。
- 开始拖动立即打断原动画，不等待旧状态 out，直接进入 dragging.in（没有则 loop）。窗口位置始终实时跟随输入，动画不阻塞拖动。
- 正常松手可播放 dragging.out，再进入最新业务状态。拖动 in 尚未完成就松手，按前述规则跳过 out。
- 错误、取消等即时反馈可跳过旧状态 out；保留既有业务优先级、latest-wins 和一次事件去重，不增加事件播放队列。
- 失焦、隐藏、pointercancel/lostcapture 等已有硬取消路径继续释放交互，不为退场延迟清理。离线、解绑、卸载仍立即移除/释放，不等待 out。
- 减少动画模式不运行过场序列，保留当前暂停/静态语义；不能依赖暂停动作的 finished 事件推进状态。

## 实施边界

复用现有 GLTFLoader、Drei/Three AnimationMixer 与共享播放器。桌面、首页和试播应采用同一套解析与阶段语义，不各自维护实现。

预计涉及：

- `packages/pet-runtime/src/actions.ts`：能力白名单、映射类型、解析和旧格式兼容。
- 宠物 manifest 解析/验证、共享数据类型及相关传递路径：确保可选阶段不会被丢弃，保持信任边界检查。
- `apps/desktop/src/renderer/shared/usePetAnimation.ts`：有限阶段推进、中断、完成回调隔离与清理。
- 桌面/首页的输入与持续状态恢复接线：区分业务状态变化和临时反馈，保留现有优先级。
- 映射展示、试播及作者模板/指南：只对获准状态呈现 in/out，清楚区分片段试播与完整序列试播。
- 对应 tests、fixtures、exports 和兼容性文档。

实施前应核对上述完整调用链，不为现有传递链已经支持的数据额外增加 IPC。不得为了本功能安装新动画引擎、引入通用时间线/队列、骨骼重定向、自动动画生成、自动混合或素材裁尾参数。

现有完成帧末姿保持及 `mixer.update(0)` 交接保护必须保留；正确播放顺序不保证片段姿态天然连续，素材衔接仍需视觉验收。

## 实施顺序

1. 确认最小向后兼容数据格式，补能力白名单与解析回归；同步作者契约。
2. 在共享播放器实现完整有限阶段切换和中断规则，先取得行为红测再实现；验证桌面与首页。
3. 接通必要的展示/试播路径，用明确配置的 in/loop/out fixture 完成端到端验证。
4. 经独立授权，在新宠物包目录中配置真实素材并人工验收，不覆盖当前已验收的空闲/移动包，不自动导入或重绑。

可以分阶段交付，但仅 in + loop 的中间结果不能宣称本文完整实现。每个独立工程阶段运行约定测试、类型检查、desktop build 和 diff 检查后本地提交；推送另行授权。

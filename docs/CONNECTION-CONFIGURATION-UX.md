# 连接区：配置管理与手动添加流程

2026-10-13。用户已选择 C 的内容方向，并要求保留原外框、顶部栏和白色页脚。本轮将此前的通信/工作监控列表收回为配置管理；下面是 UX 契约，仍待原型验收。

## 页面职责与已有证据

现有 pi 的 `PiConnectionState` 确有 configured-waiting / connected / disconnected / failed 等通信与部署状态，见 `apps/desktop/src/shared/pi-connection.ts`。因此“已连接 / 连接中断”并非完全无法识别，但它们不应作为本页的主要配置字段，也不能推出文件已失效或 Agent 已卸载。

现有 pi 的只读检查能提供 missing-target、unreadable、settings-unknown、budget 等检查结果，见 `apps/desktop/src/shared/pi-preflight.ts`、`apps/desktop/src/main/pi-preflight-files.ts`。安装候选身份检查与配置位置检查独立；目前只实现 pi 的特定接入范围，不能泛称六类 Agent 已真实支持自动识别。是否卸载必须另有程序存在性证据，单凭配置目录不存在或无通信不能判定。

**最新用户要求覆盖之前的工作状态详情方向。** 配置正常表示最近一次位置/格式等检查通过，不表示程序正在运行或收到真实工作事件。待命、工作中、完成以及通信在线情况属于首页的 Agent 状态体验。真实配置复验是否可完成、平台/版本兼容范围和检查证据必须由每类 Provider 定义，不能把“读取成功”包装成完整接入可用。

## 列表和详情

列表优先显示用户自定义名称，同时显示 Agent 类型、配置位置、配置可用性和刷新入口。两种添加入口并排、同尺寸同视觉权重：自动扫描、手动添加。不显示业务状态、通信状态或在线数量。

- 配置正常：所需检查通过；程序未运行不影响这一判断。
- 尚未检查：证据不足，不提前标绿；刷新后得到结果。
- 位置不存在：重新选择位置，不直接宣称程序已卸载。
- 无法读取：提示权限/访问问题，修正后刷新。
- 配置需修复：格式/接入条件不满足，修正后刷新或更换位置。
- 刷新检查失败或达到预算：正式版本应保留“不确定/未验证”与原因，不能降成正常或无限重试。

刷新是重新读取检查证据，必要时重载已授权配置；不会自动改写文件、重新安装扩展或重新授权。需要修复写入时，进入明确预览与确认。详情只展示配置身份、位置、可用性原因、刷新、重命名、更换位置和删除。

## 手动配置弹窗（当前方案）

用户最新要求覆盖此前独立页面方案：手动添加与更换位置均在当前连接页面打开原生模态弹窗，不新增或切换路由。参考 [Ant Design Steps](https://ant.design/components/steps/) 的 current、finish、wait、error 状态，采用三个步骤：选择位置 → 验证配置 → 命名与确认；上一步/下一步控制顺序。更换位置固定原 Agent 类型、记录身份与通信/工作字段。

1. **选择位置。** 主入口打开系统文件/文件夹选择器，另允许粘贴路径。Provider 决定支持目录、文件及所需格式；目录扫描限定必要文件，不递归读对话。取消选择保留之前输入。
2. **自动识别与只读验证。** 路径改变后撤销旧结果并重新检查；进入验证步骤后自动执行；返回修改位置撤销旧结果。检查位置存在、可读取、配置身份/结构与接入支持范围。结果须关联当前路径与类型，过期异步结果不能允许继续。
3. **补充类型，仅在必要时。** 可信格式能唯一识别则直接展示 Agent。无法识别或匹配多个类型时，提供六类类型选择；用户选择后仍执行该 Provider 验证，不允许通过选一个名字跳过验证。未支持类型不提供可成功接入操作。
4. **处理异常与重复。** 不存在、不可读、格式错误分别显示一句原因和修正动作。阻断无效继续。按实际目标身份去重，路径字符串仅是原型简化；更换位置也检查其他记录，排除自身。
5. **命名与确认。** 只在当前验证通过后进入弹窗第三步，展示识别的 Agent、来源位置和拟进行的接入动作，并允许编辑配置名称。自动扫描共用此页。名称去首尾空白、非空、最多 40 字符；不作为 ID 或去重键。真实修改遵循 MVP 精确预览/授权规则。返回保留路径、结果与用户编辑的名称；更换位置也不会覆盖自定义名称。更换位置不能静默把 pi 变成另一个 Provider。
6. **保存后。** 返回配置详情或列表，显示配置检查结论；不伪造实时在线或工作状态。失败保留选择，当前步骤修正。新增配置有独立稳定 ID，两个不同位置不会互相覆盖。

## 本轮原型边界

所有选择、验证、刷新、添加、更换与移除使用内存数据，不访问真实文件，也不调用 Electron。浏览器“选择位置”展开内置样例代替系统选择器。合法样例与 `/demo/*` 检验位置是明确登记的模拟数据；任意输入不按路径名字猜测为配置正常。

默认五个配置演示正常、位置缺失和尚未检查。自动扫描只返回七个可发现的模拟位置，跳过已缺失的 Gemini 旧位置。原型工具可演示不存在、无法读取、格式错误、未识别与多类型；未知/多类型样例选类型后重新验证。刷新可将尚未检查的有效样例变正常；缺失样例刷新仍缺失，更换合法新位置后恢复。

首页演示通信健康保留为独立字段，配置刷新不把配置有效性写成通信在线。原型标签页刷新重置数据，正式持久化、文件身份规范化、Provider 验证和真实接入仍待实现。弹窗采用 showModal 隔离背景交互、锁定焦点；Esc 或关闭按钮取消草稿并恢复入口焦点。弹窗正文独立滚动，头部步骤与底部动作保持可见。扫描添加仍使用已有确认子页面。

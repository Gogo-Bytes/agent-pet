# 按需模板

优先使用目标仓库模板。以下是无模板时的最小结构，删除不适用项；证据不足写“未验证”，不要补猜测。

## Issue

```markdown
## 目标 / 问题
<预期行为与价值；Bug 则包含实际行为、最小复现、版本/环境>

## 范围
- 本次包含：
- 本次不包含：

## 验收条件
- [ ] <可观察、可验证的结果>
- [ ] <必要的兼容性/回归保护>

## 设计与实现
- 设计：<仓库文档固定路径或链接>
- PR：<创建后填写>

## 当前进度
<没有权威 Projects 字段时才写状态；阻塞原因、解除条件和下一步>
```

创建时明确“完成”是代码合并，还是还包括产物发布/人工验收。敏感路径、凭据、用户模型或日志正文在公开 Issue 中只用脱敏证据，不上传本机私有产物。

## 阶段评论

```markdown
完成：<本阶段范围>
版本：<本地 commit 或 PR/head；明确是否已推送>
验证：<命令/结果，或 CI 链接>
未测/阻塞：<范围及原因>
下一步：<一个明确行动>
```

## PR

```markdown
## 关联任务
<普通 Issue 引用，或确认可在合并时关闭后的 Fixes 引用>

## 变更
- <本 PR 的单一目的和关键实现>

## 验证
- <命令及实际结果>
- <远程 checks 状态另列，不与本地结果混淆>

## 风险与未完成
- <兼容性、数据/回滚风险、未测环境、后续 PR 或验收>
```

## 验收记录

```markdown
版本/产物：<SHA、tag、包版本>
环境/执行者：<实际环境，用户反馈或自动化需标明>
通过：<明确场景>
失败/未测：<明确场景>
结论：<可关闭 / 仍待验收 / 阻塞；承接任务链接>
```

## 触发示例

- “记录这个 Bug”：定位仓库、查重、整理复现与验收；有创建授权才发 Issue，不自动修复。
- “继续 #42”：核对仓库与 Issue 最新状态、现有 PR/head 和工作区，然后恢复未完成阶段。
- “把这些改动提 PR”：核对 diff、待推历史、验证及授权；需求含人工验收时不自动关闭 Issue。
- “合并后怎么还没完成”：检查完成定义与发布/验收证据，不从 merged 推导验收通过。
- “把计划迁到 Issues”：先预览活跃任务与去重结果，获授权后迁移并切换状态归属。

# 桌面产品与一键接入设计（评审草案）

状态：**产品方向及本文件末尾四项决策已确认。P0 已形成研究与有界验证，P1 核心交互已实现并获用户确认，当前推进 P2 分段实施。** 本文保留最初设计背景；实际交付状态以对应阶段验收文档为准，不将后续建议写成已实现。

当前入口：[P0 契约](P0-INTEGRATION-CONTRACT.md)、[P1 核心交互与待验收项](DESKTOP-P1-FOUNDATION.md)、[P2 分段实施](DESKTOP-P2-IMPLEMENTATION.md)。

现状基线：`cff267b`，React/R3F 迁移后的桌宠。本方案不更改代码、依赖、系统配置或用户 Agent 设置，不启动或重启 Agent，不推送。具体实现阶段须在本方案确认后启动。

## 1. 已确认目标与非目标

用户已确认：

- 安装后通过图形界面使用，不要求终端、环境变量、复制 token 或编辑配置文件。
- 除桌宠外，需要管理界面，用于选择宠物、发现/手动选择本机 Agent、接入及后续扩展。
- 先规划设计再实施。

继续保留：一个宠物对应多个独立 Session；只读观察，不发消息、不审批、不暂停/恢复 Agent；不读取对话正文；Agent 原生使用方式不变；历史 unread 不跨应用重启保留。

“永久可用”应落实为持久配置、启动恢复、断线重连和可修复升级，不承诺跨所有 Agent 版本永不失效。“安装即用”指用户无需开发环境；首次接入仍需知情授权，已运行会话可能需要用户在安全时机重载或重启。

非目标：本轮不实现 Codex/Claude 接入、不做市场/云同步/账号、不做任意脚本插件系统、不扫描所有进程或会话文件。现有原 Session 窗口定位仍 unsupported，不以接入管理掩盖限制。

## 2. 当前事实与差距

| 当前实现事实 | 产品化差距 |
| --- | --- |
| Main 只有一个透明 petWindow，Application 快照只发给它 | 需要独立管理窗口与按窗口授权的 IPC，而非放宽现有 trusted-renderer 校验 |
| piConfig 启动时从环境变量读取，扩展也在加载时读取并固定 endpoint/token | 无法仅靠增加设置页面实现永久自动发现；双方连接配置机制必须改变 |
| pi extension 是用户手工加载的自包含 TS 文件 | 需要经验证的安装目标、所有权记录、版本管理和撤销操作 |
| 断线会重试，hello 使用当前 working/idle 基线 | 可复用语义，但需动态重读发现信息以支持应用重启和凭证更新 |
| 使用 bundled starter.glb，一个模型 | “切换形象”需要至少两个合格且授权清晰的内置资产，不可展示无效选择 |
| 已有本机有界验收，尚有 Windows、功耗、长期稳定性及安全风险 | 不能把产品包装误称为跨平台正式发布验收 |

依据：`apps/desktop/src/main/index.ts`、`main/pi-config.ts`、`src/preload/index.ts`、`integrations/pi-extension/index.ts`、`docs/RENDERER-R4-ACCEPTANCE.md`。

`PRODUCT-REQUIREMENTS.md` / `CONTEXT.md` 中初期的多 Agent、自定义 GLB 范围不是已经交付的能力；本草案建议将当前产品化切片限制到 pi 和内置资产。评审通过后再同步正式需求，避免草案直接覆盖已有规则。

## 3. 产品形态建议

**一个应用、一个主进程、两种窗口、一个托盘/菜单栏入口。** 不做第二个独立桌面程序或本地 Web 服务。

| 界面 | 职责 | 不承担 |
| --- | --- | --- |
| 桌宠浮层 | 3D 宠物、Session 气泡、轻量快捷操作、进入管理窗口 | 安装向导、复杂表单、诊断详情 |
| 管理窗口 | 接入、宠物选择、偏好、故障处理 | 独立的 Session 状态机或第二个桥接服务 |
| 托盘/菜单栏 | 打开管理窗口、显示/隐藏宠物、退出 | 任意 Agent 控制 |

首次启动打开管理窗口并展示默认宠物；未连接 Agent 也能欣赏宠物，允许跳过向导。

建议关闭管理窗口只隐藏该窗口，桌宠与桥接继续运行；首次关闭提示一次。退出应用才停止全部窗口与桥接。双击应用重新打开管理窗口，不启动第二个桥接服务。需要单实例保护。

建议登录自启默认关闭，首次配置以明确开关供用户选择。只有启用自启才能承诺用户登录后无需再打开 Pet；不得暗中增加登录项。全隐藏仍可从托盘找回。

## 4. 管理窗口信息结构

首版导航采用三个主页面，避免空洞仪表盘：

1. **Agent 连接**（默认首页）：接入卡片、在线会话数、待处理事项。
2. **宠物**：当前形象、预览、内置选择、大小、显示/隐藏。
3. **设置**：启动与显示偏好；诊断与关于作为分区，不单独占一级导航。

```text
┌ Agent Pet ──────────────────────────────────────────┐
│ Agent 连接 │ 让宠物关注你的工作                       │
│ 宠物       │ 只观察名称和状态，不读取对话内容           │
│ 设置       │                                          │
│            │ pi                              [重新检测]│
│            │ 已找到 · 默认用户配置                    │
│            │ 尚未接入                         [连接]  │
│            │                                          │
│            │ 没找到安装？ [选择位置]                   │
│            │ 在线会话只在完成验证后显示                │
│            │                                          │
│            │ 其他 Agent：暂未支持（无可用连接按钮）    │
└───────────────────────────────────────────────────────┘
```

连接后的卡片：

```text
pi · 默认配置                         已配置 · 等待会话
扩展已准备好。之后正常打开 pi 即可连接。
已有 pi 正在运行？请在空闲时重载或重新打开。
[查看步骤] [重新检查] [更多：修复 / 断开]
```

收到经过身份/协议验证的连接后：`已连接 · 2 个会话`。工作/完成等 Session 状态仍由 Application 决定，不与安装状态混在一起。

宠物页：一处预览、资产名称/作者/许可、选择列表、`应用此形象`、尺寸选项。预览选中不立即替换正在使用的模型；成功加载后原子切换，失败保留原模型。管理窗口关闭或预览不可见时暂停预览，不常驻双重高帧率渲染。

布局风格：管理窗口使用可读性优先的常规不透明面板、清晰分组和统一 tokens；桌宠保留轻量玻璃视觉，不把整页设置做成透明悬浮面板。支持键盘、焦点、缩放、减少动态效果。

## 5. 首次接入流程

```text
安装并打开 → 默认宠物可用 → 检测支持的安装位置
    ├─ 未找到：选择位置 / 重新检测 / 暂时跳过
    ├─ 找到多项：选择本次要配置的目标（不自动批量修改）
    └─ 找到可用目标：显示接入说明 → 用户点击“允许并连接”
         → 检查权限与冲突 → 安装受管理扩展 → 检查安装结果
         → 等待正常打开的 pi / 提示已有会话需重载
         → 收到兼容且认证的握手 → 已连接
```

授权页需说明：修改哪一个用户配置范围、会安装可执行扩展、采集会话名称/项目名和粗粒度状态、仅本机通信、不会读取正文/控制 Agent，以及如何撤销。默认不显示秘密和技术表单；高级详情可查看脱敏路径。

人工选择位置是图形化文件/目录选择器，不要求复制路径。选中任意文件不等于安装有效，不通过执行未知二进制来验证。无法确认时保留“候选位置未验证”而非成功。

## 6. 状态设计：三个独立维度

不将所有状态压进一个“已连接”开关：

| 维度 | 内部含义 | 用户表达示例 |
| --- | --- | --- |
| 发现 | 未检测/候选/有效目标/找不到/多候选 | 找到 pi；请选择配置目标 |
| 配置 | 未授权/安装中/已配置/冲突/需修复/已撤销 | 扩展已准备好；安装未完成 |
| 运行 | 等待/已验证在线/断开/不兼容 | 等待会话；已连接2个会话；需要更新 |

单个 Session 结束不能将整个 Agent 标为断线。没有正在运行的 pi 是正常等待，不是错误。静默空闲也不是失联；若要显示连接健康，需要明确的连接级 liveness，而不是把没有业务事件当掉线。显示最后检查时间，协议不兼容必须显式说明。

## 7. 主要异常与用户操作

| 情况 | 用户看到什么 | 产品行为 |
| --- | --- | --- |
| 没装 pi | 未找到，可稍后连接 | 宠物仍可用；可提供官方安装说明，但不静默安装 Agent |
| GUI PATH 找不到终端里的 pi | 自动检测未找到 | 提供位置选择，不要求修改 shell 配置 |
| 自定义配置目录/多份 pi | 需要选择目标 | 默认支持标准用户目录；其它目标只在能力验证后启用 |
| 扩展文件已存在/被用户修改 | 检测到冲突 | 显示差异摘要或保留原文件，不覆盖未知所有者内容 |
| pi 正忙 | 已配置，等待安全加载 | 不自动重启或重载；继续允许用户工作 |
| Pet 未运行或退出 | pi 正常工作 | 扩展非阻塞重试，受控退避，不阻碍 Agent 退出 |
| 应用升级、旧扩展还在运行 | 兼容继续/需重载 | 不伪装在线；支持约定兼容窗口和修复入口 |
| 配置/权限损坏 | 需要修复，附具体原因 | 一键重检/修复预览，不要求用户看控制台 |
| 用户断开 | 已停止接收 | 先撤销服务端授权并关闭既有连接，再清理自有安装；正在运行的扩展即使尚未卸载也不再获准接入 |
| 文件已被外部修改 | 已断开，部分文件保留 | 不恢复整个旧配置覆盖新改动；指导用户查看剩余项 |

## 8. 架构建议与安全边界

```text
管理 Renderer ── 专用 preload ── 管理命令/查询 ─┐
桌宠 Renderer ── 现有窄 preload ── 宠物 IPC ────┤
                                                Main
                       ┌─────────────┬───────────┴─────────┐
                 Preferences   IntegrationService    Application
                                    │                     ↑
                    Discovery / ManagedInstaller     pi Adapter
                                    │                     ↑
                          受管理的 pi 扩展 ── 本机桥接 ────┘
```

建议把 Main 的窗口生命周期与接入编排拆开，而不直接把设置逻辑堆入当前 `index.ts`。Domain/Session 规则保持独立；安装与用户偏好不成为 Session 状态。

- 每个窗口单独识别 webContents/mainFrame、允许的入口与 IPC 能力；管理窗口不能获得任意文件读写或 shell。
- Renderer 传目标 ID 和受约束选项，Main 执行预览/确认/应用。文件选择由 Main 发起并再次校验，不能信任 Renderer 提交路径。
- 不加载远程管理网页或远程脚本，不通过新管理窗口放宽 petWindow 导航策略。

### 8.1 连接发现的方案比较

A. 环境变量/特殊启动命令：可作为开发入口，但不满足正式体验。

B. **推荐：用户级、受权限保护的 rendezvous 描述文件 + 本地 socket/pipe**。Pet 监听成功后发布协议版本、实例标识、连接位置和非秘密凭证引用；扩展在连接/重试时读取，不要求用户维护。描述文件与秘密存储分离，凭证取用方案见下节。

C. 常驻后台服务/daemon：可在 UI 未启动时服务，但引入额外安装、升级、权限与卸载负担。首版不采用；用用户可选登录自启解决常用场景。

B 仍需实施前验证：macOS 标准用户目录与 Windows 路径如何在 Electron 和 pi Node 侧一致解析；Unix socket 路径长度；Windows named pipe ACL。不能直接使用世界可读临时文件或无权限限制的固定端口。

### 8.2 凭证与配置

区分三类存储：

- 偏好：所选宠物、尺寸、自启、显示偏好，带 schemaVersion，原子写入，损坏时回退并提示。
- 接入所有权记录：用户授权目标、安装版本、修改前后摘要、自有文件标识；用于幂等安装、更新和选择性撤销。
- 运行发现/凭证：不进入 Renderer、日志、截图、诊断导出或仓库；服务重启可换代，扩展重新发现。

POSIX 目标是用户私有目录/文件和 socket 权限；Windows 必须验证仅当前用户可访问的 ACL。检查 symlink/所有者与替换竞态，读写有大小上限；无法安全设置权限则明确失败，不悄悄退化。

凭证存储尚不冻结：比较 OS 凭证库 + 窄访问 helper，与按目标隔离的私有权限 token 文件。前者需验证 pi Node 侧取钥及签名/安装成本，不能假设扩展能直接调用 Electron safeStorage；后者是权限保护的明文而非系统加密存储，必须明确风险并在 P0 评审。选定方案失败时不静默降级。

这是同一 OS 用户权限边界，不承诺隔离同用户恶意软件。P0 收敛建议见 [本机安全边界](P0-LOCAL-SECURITY-DECISION.md)：首版私有 UDS + 按目标 token，不要求连接证书/TLS。hello/ack 用于准入与版本确认，不能称为双向密码学身份认证；其它 OS 用户防护依赖实际目录/路径/ACL 验证，不宣称抵御同 uid 冒充。该建议替代早期把 TLS 当成必要条件的倾向，尚待完整技术评审。不得自创密码协议；仍需认证超时、连接数/速率上限与异常隔离。

“握手在线”仅证明组件连接，不证明生命周期语义全部正常；首次正常工作→完成仍是单列验收。

断开应立即使授权失效，不仅删文件。升级/轮换必须处理已建立连接，不允许旧连接继续无限接收。退出清理只删除属于当前实例的运行文件，避免误删新实例文件。

### 8.3 扩展安装与兼容

首选验证 pi 官方支持的用户级自动加载机制，安装产品专属、自包含扩展文件，尽量不重写共享 settings。如果官方机制要求注册，则最小粒度合并指定项。

P0 已静态核实 pi 0.85.1 标准发行版的用户自动发现及重载边界，见 [P0 契约](P0-INTEGRATION-CONTRACT.md)；仍**未核实所有 pi 版本、profile、自定义目录的加载和重载契约**，不能直接把固定路径写成通用正式接口。检测不扫描会话正文，不启动 pi 来判断安装；安装位置与用户配置目标是两个概念。

安装过程：读取并校验目标 → 生成变更预览 → 用户授权 → 防并发校验 → 暂存并原子应用 → 验证文件状态 → 记录可撤销信息。失败恢复本次自有变更；不覆盖安装期间出现的用户修改。

扩展随应用提供，避免在线运行任意安装脚本。优先稳定加载入口与版本化 payload，具体采用复制/加载器方案须验证 pi 能力与签名包路径约束。兼容协议显式协商；升级失败仍保留可用旧版或清楚报告需重载。

正常 OS 卸载不保证执行应用清理回调。提供“断开并移除接入”入口；如果用户直接删除 Pet，残留扩展必须安全惰性退出/有界重试，不报错刷屏、不保活、不影响 pi。重装时识别自有残留并请求恢复，而非重复安装。

## 9. 宠物与发布范围

首个可交付闭环：管理窗口 + pi 一键接入 + 当前内置模型设置。用户已确认首版不需要第二种模型；继续使用现有模型，只有一个模型时展示“当前宠物”，不展示虚假的形象选择库。后续模型由用户提供，再按许可、安全、性能和动画契约评估与适配；未经另行授权，Agent 不自行制作或获取替代模型。形象切换保留为后续设计，不阻塞首版。

自定义 GLB 导入是独立后续阶段：需要复杂度、安全、外部资源、动画和失败回退验证，不在设置页加文件选择器就宣称支持。无市场、在线下载、任意模型脚本。

正式“安装可用”还必须包括自包含安装包，不依赖用户 Node/pnpm、源码目录或 shell PATH；签名/公证、Windows 签名、更新与分发渠道属于发布决策，不因界面实现完成而省略。证书/平台账号需要用户授权和预算，不能自动代办。初版可先手动安装新版；自动更新需单独确认渠道、签名校验与回滚策略。

## 10. 设计确认后的实施分段（尚未开始）

| 阶段 | 交付 | 独立验收 |
| --- | --- | --- |
| P0 可行性核实 | 官方 pi 安装/自动加载/自定义目录/卸载契约；连接发现协议与威胁边界；页面状态稿 | 每项能力有依据或明确不支持；不改真实用户配置 |
| P1 桌面管理基础 | 管理窗口、托盘、单实例、偏好、窗口权限隔离 | 关闭/重开不丢状态、不杀 Agent；无管理 IPC 越权；原桌宠流程不回归 |
| P2 pi 一键接入 | 发现、选择目标、授权安装、动态发现、状态、修复与断开 | 无终端配置；新 pi 正常启动可握手；升级/重启可恢复；断开立即拒绝旧连接；冲突不覆盖 |
| P3 当前宠物设置 | 现有模型预览、尺寸与显隐偏好；不新增模型 | 重启保留偏好；不可见预览不持续渲染；用户后续提供模型后再独立安排适配与切换 |
| P4 macOS 预览版安装验收 | 自包含安装包、首次使用、升级、卸载说明与诊断 | macOS 干净机器无开发环境可用；跨用户权限隔离；明确预览版限制；Windows 实机验证完成后再单独发布 |

这些阶段不是对当前 R0–R4 的重编号。每阶段测试、类型、构建与相应实机证据独立交付，用户允许前不推送。代码阶段仍需独立提交，设计草案不强行提交。

## 11. 用户可观察的验收清单

- 安装后不用终端即可看见宠物，未装 Agent 也不报致命错误。
- 自动检测失败时能点选位置；不把任意可执行文件当支持的 Agent。
- 点击一次明确授权后，之后正常打开 pi 即连接，不重复询问或要求 token。
- 已有忙碌 pi 不被重启，界面准确说明何时生效。
- 两个 pi 会话独立显示；关闭一个不将另一个误判离线。
- Pet 重启后在线工作基线恢复，不重放离线历史完成通知。
- 管理窗口和桌宠互不阻碍；全部隐藏后可从托盘恢复。
- 断开不删用户其它扩展、不覆盖用户新修改；撤销立即生效。
- 更新/重装不重复安装、不破坏授权目标；不兼容时不显示绿色成功。
- 诊断导出默认脱敏，不含 token、对话、完整 Session 名称或用户绝对路径。
- Windows 未测则不标正式支持；长期功耗/安全审计未关闭则如实列出。

## 12. 用户评审结论与待验证项

用户已明确确认：

1. 管理窗口以 **Agent 连接**为首页。
2. **关闭管理窗口继续运行桌宠与桥接；登录自启默认关闭**，由用户选择开启。
3. **首版无需第二种宠物形象**。后续由用户提供模型，再做适配；Agent 不自行制作模型。当前模型设置即可，不以模型数量阻塞产品化。
4. **先交付 macOS 预览版**；Windows 完成实机验证后再发布，不提前宣称支持。

继续维持 pi 优先、只读观察、首次知情授权和零手工开发配置的方向。待 P0 核实的技术项包括 pi 自动加载机制、受支持配置目录、凭证访问与双向认证、安装撤销及发布签名条件；这些没有因产品方向确认而自动成为已验证事实。

以上是首次产品评审决定。后续用户已批准并验收 P1 核心流程，目前同意继续 P2；真实 Agent 配置写入仍须通过安装阶段门槛及产品内明确授权，不能由阶段推进推断对当前用户配置的安装许可。

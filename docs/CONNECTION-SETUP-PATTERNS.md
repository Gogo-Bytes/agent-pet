# 连接区：手动添加交互参考

2026-10-13。范围是浏览器 UI 原型；参考官方设计系统的流程原则，不移植其企业视觉风格。现有配置职责见 [配置管理与手动添加流程](CONNECTION-CONFIGURATION-UX.md)。

## 官方案例与可借鉴点

| 案例 | 官方指导 | 本项目采用方式 |
| --- | --- | --- |
| [GOV.UK Check answers](https://design-system.service.gov.uk/patterns/check-answers/)（页面含可打开的示例及 HTML） | 提交前集中复核；提供修改入口；返回时预填已有内容，修改完直接回复核页 | 添加前确认名称、Agent 类型、完整位置；更换位置返回原选择页，不要求再走一次其他内容 |
| [Carbon Progress indicator](https://www.carbondesignsystem.com/building-blocks/core/components/progress-indicator/guidelines)（页面含 live demo） | 用于至少三个线性步骤；少于三个步骤、步骤数量变化时不宜使用；步骤名描述用户完成的动作 | 识别/检查是自动处理状态，不凑成一个用户步骤。短流程不占用大块侧栏或三段进度条 |
| [PatternFly Wizard](https://www.patternfly.org/components/wizard/design-guidelines/)（含完整页、复核和完成页设计图） | 复杂任务按步骤拆分；简单表单无需 wizard；页内流程要管理未保存状态；主动作唯一；完成动作应指向结果 | 在既有外框里使用子页面，保存 draft；每页一个主动作；添加后返回新配置或列表 |
| [GOV.UK Question pages](https://design-system.service.gov.uk/patterns/question-pages/) | 页面标题对应当前问题；先降低问题数量，再考虑进度指示；提示应简短 | 标题「选择配置位置」「确认添加」，不重复大标题「连接」；复杂帮助放展开区 |
| [GOV.UK Recover from validation errors](https://design-system.service.gov.uk/patterns/validation/) | 错误后保留输入，在字段附近解释问题；不宜在用户尚未输入完时反复报错 | 路径不清空，原因和修复动作放在位置输入下面；正在输入时不闪红色错误 |

## 推荐流程：两个操作页

以下为针对 Agent Pet 的设计推导，不是上述系统对本产品的规定。

### 1. 选择配置位置

- 「选择位置」打开系统文件/文件夹选择器，旁边允许粘贴路径；取消选择不清空旧值。
- 选择器返回后自动识别 Agent、检查位置与结构，在同页显示「正在检查」→结果。粘贴输入应等待输入稳定或明确提交后检查，避免每个字符都触发错误。
- 识别唯一类型后显示 logo + Agent 类型 + 检查结论，不让用户再选一次类型。
- 未识别或多种匹配时才展开类型选择，随后重新验证；用户选名称不等于检查通过。
- 主动作「继续」仅在当前目标通过检查时可用；底部始终说明阻断原因，不能只留灰色按钮。

### 2. 确认添加

- **连接名称可编辑**，提供可直接使用的默认值，例如「Codex · 日常配置」；同类第二个位置可默认「Codex · 项目配置」或序号，不强迫用户起名字。
- 展示 Agent 类型与完整配置位置，提供「更换位置」；确认按钮明确叫「添加连接」。自动扫描和手动添加共用这一页，二者都允许命名。
- 返回修改位置保留已编辑名称。用户主动改过名字后，识别结果更新不能覆盖它。
- 保存失败留在当前页并保留输入；成功可直接进入新记录详情，避免再加一个没有操作价值的独立庆祝页。

两页可用轻量「1 / 2」辅助方向感；无需独立「验证」页。若正式 Provider 后续确有权限、安装动作，只有新增了真实用户决策才扩展步骤，接入预览和授权仍遵守当前 MVP 契约。

## 名称、身份与删除

- 名称是用户可改的显示字段，Agent 类型和稳定配置 ID 独立。列表优先名称，同时保留类型与路径，避免两条同名记录不可区分。
- 名称建议支持中文、空格等日常命名，去除首尾空白；空名称提示「请输入连接名称」。字符上限由实现明确，本轮原型可设 40 字符；不应因同名覆盖记录。重复目标仍按目标身份阻断，与重命名无关。
- 已有配置详情提供「重命名」和「删除连接」；删除确认应同时显示名称、类型、完整位置。
- 「删除连接」只表达移除 Agent Pet 里的配置，明确不删除用户的 Agent 文件。正式接入若包含扩展撤回，要另展示准确动作；不能通过文案默认承诺全部清理。

## 自动验证的分歧与取舍

Carbon 建议离开字段时做 inline validation；GOV.UK 偏向点击继续后验证，提醒即时错误会干扰慢速输入。[Carbon 验证说明](https://www.carbondesignsystem.com/building-blocks/core/components/progress-indicator/guidelines)、[GOV.UK 验证时机](https://design-system.service.gov.uk/patterns/validation/)。

本项目文件选择是一个已完成的选择动作，可立即检查；文本输入只在稳定后检查，输入过程中撤销旧结果、收起旧错误。过期异步结果不改变当前页面。保存前再检查真实目标，以免复核期间文件变化。这是产品取舍，需后续实际用户测试确认。

## 本轮自评检查项

- 同一种 Agent 的两条记录能分别命名、刷新、删除，操作不会落到另一条记录。
- 自动扫描添加也可编辑名称；回到位置选择后名称不丢失。
- 错误状态保留路径，说明具体原因与下一步；检查中没有旧结果允许继续。
- 返回、跨首页/连接切换不重置未提交输入；窄窗口操作区无横向溢出。
- 删除确认读取当前记录名称与位置；删除后的其他配置保持原样。
